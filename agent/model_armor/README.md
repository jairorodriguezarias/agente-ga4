# Vertex AI Model Armor Integration

This directory contains the resources for integrating Vertex AI Model Armor with the agent.

## Purpose

The goal of this integration is to add a layer of security to the interactions with the Gemini models used by the agent. Model Armor inspects the prompts sent to the model and the responses generated by it, helping to detect and mitigate potential harms or policy violations.

## `setup_model_armor.sh`

This script automates the setup process for Model Armor at the project level.

### What it does:

1.  **Fetches Project Details:** It automatically retrieves your active Google Cloud Project ID and Project Number.
2.  **Grants Permissions:** It grants the necessary IAM role (`roles/modelarmor.user`) to the default Vertex AI service account (`service-PROJECT_NUMBER@gcp-sa-aiplatform.iam.gserviceaccount.com`). This allows Model Armor to access and inspect the AI Platform resources.
3.  **Configures Floor Settings:** It sends a request to the Model Armor API to enable project-wide inspection for all `generateContent` calls made to Gemini models.
    *   `"inspect_only": true`: This setting ensures that Model Armor only inspects and logs findings without blocking any requests. This is a safe setting for initial setup.
    *   `"enableCloudLogging": true`: This ensures that all findings from Model Armor are sent to Cloud Logging for visibility and analysis.

### How to use:

The script is designed to be run from the root of the `agente-ga4` project.

1.  **Ensure you are authenticated with gcloud:**
    ```bash
    gcloud auth login
    gcloud config set project YOUR_PROJECT_ID
    ```

2.  **Run the script:**
    ```bash
    ./agent/model_armor/setup_model_armor.sh
    ```

### Expected Outcome

After running the script, Model Armor will be active for your project. You can verify this by:
1.  Making calls to a Gemini model in your project.
2.  Navigating to **Cloud Logging > Log Explorer** in the Google Cloud Console and filtering for logs related to Model Armor to see the inspection results.

### Verifying Findings in Cloud Logging

You can use the `gcloud` command-line tool to query Cloud Logging for Model Armor reports. These commands are useful for quickly checking if your filters are being triggered.

**Note:** It may take a minute or two for logs to appear after a request is made.

#### General Command

This command will show the most recent reports from Model Armor, regardless of the finding type.

```bash
gcloud logging read 'resource.type="model_armor_report"' --project=YOUR_PROJECT_ID --limit=20 --format=json
```

#### Specific Commands by Category

These commands filter for specific Responsible AI categories.

*   **Dangerous Content:**
    ```bash
    gcloud logging read 'resource.type="model_armor_report" AND jsonPayload.request_info.matched_info.finding_type="DANGEROUS"' --project=YOUR_PROJECT_ID --limit=5 --format=json
    ```

*   **Hate Speech:**
    ```bash
    gcloud logging read 'resource.type="model_armor_report" AND jsonPayload.request_info.matched_info.finding_type="HATE_SPEECH"' --project=YOUR_PROJECT_ID --limit=5 --format=json
    ```

*   **Harassment:**
    ```bash
    gcloud logging read 'resource.type="model_armor_report" AND jsonPayload.request_info.matched_info.finding_type="HARASSMENT"' --project=YOUR_PROJECT_ID --limit=5 --format=json
    ```

*   **Sexually Explicit:**
    ```bash
    gcloud logging read 'resource.type="model_armor_report" AND jsonPayload.request_info.matched_info.finding_type="SEXUALLY_EXPLICIT"' --project=YOUR_PROJECT_ID --limit=5 --format=json
    ```
